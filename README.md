## 为什么需要它

脑机接口在 2026 年同时出现了两个相反的事实: 一边是资本与政策的集中涌入, 一边是绝大多数标的无法用同一把尺子衡量。

真正的问题不在「看不看好这个赛道」, 而在**用错了尺子**:

- 植入式三类产品与消费级脑电头环, 研发周期、资金消耗、壁垒高度、退出路径完全不同。前者可以用里程碑折现的期权思路讨论, 后者只能回到收入、扣非利润、市占与复购。**把消费级资产按硬科技期权定价, 是这个赛道最贵的错误。**
- 单项监测设备 (只有采集, 没有实时解码与反馈) 常被包装成脑机接口平台。监管口径对此已有明确边界, 尽调必须先做这一层判定。
- 长周期赛道与短存续期基金错配, 常被误读为「项目选错了」。同样的标的, 换一种资金属性结论可能完全不同。

本框架把这三类问题前置成**门禁**, 再用九个维度、109 项检查项与 44 条红旗逐层收敛, 最后把评分、跑道、里程碑定位、估值偏离与股权穿透交给两个确定性脚本完成 —— 数字不靠口算, 结论可被复算。

## 快速开始

零依赖, 只需 Node ≥ 18。

```bash
git clone https://github.com/StringXD/bci-investment-dd.git
cd bci-investment-dd

# 看输入格式与输出结构(内置示例故意埋入多处告警)
node scripts/dd_score.mjs --example
node scripts/ownership.mjs --example

# 用自己的数据跑
node scripts/dd_score.mjs examples/01-implant-class3.json
node scripts/ownership.mjs examples/03-cap-table.json
```

输出是 Markdown, 可直接粘进尽调报告。第一至七节的表格与数字**逐字粘贴**, 报告模板的节号与脚本节号一一对应。

### 换口径: 用参数集, 不改源码

内置权重与倍数区间是结构示意值, 本来就该按自己基金的偏好校准。校准结果放在一份**独立**的参数集文件里, 用 `--config` 传入:

```bash
# 以内置默认值为起点, 导出成可编辑的参数集
node scripts/dd_score.mjs --print-defaults > fund-2026q4.json

# 改完再跑; 覆盖生效时 banner 会标注参数集指纹
node scripts/dd_score.mjs data.json --config fund-2026q4.json
```

为什么不把参数写进标的输入: 参数按季度失效, 标的输入按项目失效; 混在一个文件里, 「转发给同事做复核」就变成了「顺手泄露机构权重」, 而且报告无法区分「参数变了」还是「标的数据变了」。

参数集不合法时脚本以 `exit 2` 中止并逐条列出 `V-01` 至 `V-19` 的编号 —— **参数错了, 算出来的每个数都是错的, 不存在「部分可用」**。空参数集与默认值往返的等价性, 以及三份示例的可复现性, 由 `bash tests/run.sh` 守护:

```bash
bash tests/run.sh    # 27 项断言
```

有一类参数锁死不可覆盖: 红旗的编号与等级、`allow_option`、门禁判定逻辑、里程碑主干路径、监管编码。允许改红旗等级等于允许把一票否决降级 —— 这是框架唯一不开的口子。

### 机器可读输出

终端报告是给人扫的。要排版成可交付文档、把多个标的排成一列、看同一标的跨季度怎么变, 都需要结构化结果:

```bash
node scripts/dd_score.mjs data.json --json
node scripts/ownership.mjs cap.json --json
```

输出 `{ schema, script_version, ... }`, 其中 `schema` 为 `dd-score-output/1` 或 `ownership-output/1`, 其余字段即 `analyze()` 的全部中间结果: 维度行与加权贡献、未完成检查项、红旗状态、跑道档位、隐含倍数与偏离、结论与封顶原因、证据缺口、警告, 以及 `paramsMeta`(参数集指纹与溯源状态)。

为什么不直接解析终端 Markdown: 那等于把排版细节变成接口。报告里调一次列宽、换一个标点, 所有下游就静默断掉, 而且错得很像对。JSON 的字段在次版本内只增不减, 下游应忽略不认识的键。

`--json` 与默认输出来自**同一次计算**, `tests/run.sh` 断言两者的分数必须完全一致 —— 否则就等于维护了两套逻辑。

### 输出语言

报告是双语的: `--lang zh-CN`(默认)或 `--lang en-US`。

```bash
node scripts/dd_score.mjs data.json --lang en-US
node scripts/ownership.mjs cap.json --lang en-US
node scripts/dd_score.mjs --print-defaults --lang en-US   # 参数集标签跟着走
```

定义语言与数字量级彼此独立。美元标的的中文报告读作 `USD 12.5 亿`, 人民币标的的英文报告读作 `CNY 1.25B` —— 两边各用自己习惯的进位, 币种从不被默默假定。

这一版围绕三条规则构造:

- **中文输出与 v0.4.0 逐字相同。** 中文串内联在调用点, 作为 `t(key, "中文", vars)` 的默认值, 英文词表是唯一的查表。若做成中英对偶词表, 一次「顺手润色」就能静默改掉中文, 而中文输出正是全部 golden 的比对基准。
- **英文缺键是硬错误(exit 2), 不回落中文。** 回落产出的是一份半翻半不翻、却渲染成功的报告 —— 对交付物而言这是最坏的失败方式。
- **不支持的 locale 同样 exit 2。** 没有「就近匹配」: `en` 与 `en-US` 若行为不同, 报告就不再可复现。

`assets/i18n/zh-CN.json` 是生成出来的镜像, 不是真源。改过任何用户可见文案后跑 `node tools/dump-catalog.mjs` 重新生成; 镜像漂移时 `node tools/dump-catalog.mjs --check` 会让构建失败。

## 九维与里程碑

| 维度 | 检查项 | 看什么 |
|---|---|---|
| D1 资产属性与估值范式 | 13 | 叙事线与收入线是否错位, 口径族是否选错 |
| D2 临床需求与适应症价值 | 10 | 风险收益比是否成立, 是否存在低风险替代 |
| D3 技术真实性与工程化 | 14 | 在线闭环、跨被试泛化、六件套完整性、伪前沿识别 |
| D4 注册路径与临床证据 | 14 | 分类界定、型检时点、对照设计与主要终点 |
| D5 商业化与支付 | 12 | 谁付钱、付多少、能否复制 |
| D6 财务质量与现金跑道 | 11 | 剔除补助与关联方后的经营性收入 |
| D7 资本结构、条款与退出 | 11 | 退出通道硬门槛、回购压力、估值倒挂 |
| D8 法律、IP、数据与控制权 | 12 | 权属链、知情同意、宣传合规 |
| D9 组织、创始人与产业生态位 | 12 | 单点依赖、关键角色缺位、BD 能力 |

里程碑七级 (L0 → L6), 每级对应一组可验证证据, 也是估值跳升的唯一合法依据:

`L0 原理验证 → L1 型式检验与标准符合性 → L2 大动物安全性 → L3 探索性临床 → L4 多中心确证性 → L5 注册申报与审评 → L6 注册证与商业化准入`

二类康复与消费级走分支路径, 不经过大动物实验与确证性临床 —— 这是资产属性分流在流程上的体现。

## 工程约定

- **零依赖。** 只用 Node 标准库, 不联网, 不写文件, 输出到 stdout。
- **能算多少算多少。** 输入缺失只产出 `## 警告`, 不抛异常: 问题集中到最后一段, 每条带主体名与具体数值。
- **节号是契约。** 脚本输出 `## 一` 至 `## 七` 与末段 `## 警告`, 报告模板按同一套节号组织, 三方对齐。
- **参数可校准。** 权重、阶段因子、倍数区间、里程碑耗时都是常量表, 属方法学假设而非市场事实。换口径用 `--config` 传独立参数集, 并在报告里声明版本与指纹。
- **不口算。** 所有数字以脚本 stdout 为准, 禁止四舍五入改写或在报告里补算脚本没输出的指标。
- **可复算。** 同一份输入 + 同一份参数集, 任何时候跑出同一份报告; 覆盖生效时输出带 `params: <id>@<hash8>`, 把它填回 `meta.params_ref` 即可闭环。

## 方法论溯源

本框架由三部分合成:

1. **结构化尽调骨架** —— 六维清单 (业务 / 财务 / 法律 / 技术 / 临床监管 / 团队) 与 25 条红旗 (14 🔴 + 11 🟡) 的原始积累, 整体迁入九维, 无条目丢失; 逐条归宿见 [`references/red-flags.md`](references/red-flags.md) 附录 B。
2. **股权控制类尽调的工程范式** —— 「数字以脚本为准、references 按阶段门禁、报告模板与脚本节号互锁」的组织方式, 使方法论从文档变成可执行流程。
3. **行业公开观察的概念贡献** —— K 型分化的资本结构、医疗级与消费级两类资产的估值范式鸿沟、里程碑与估值跳升的对应关系、期权定价思路在长周期硬科技上的适用前提。这些属观点与框架性判断, 具体数字一律按 [`references/sourcing-rules.md`](references/sourcing-rules.md) 的级别要求重新核验, 未核者进待核区, 不进结论。

监管与标准事实均登记在 [`references/sources.md`](references/sources.md), 含发布日、访问日与级别, 例如:

| 事实 | 来源级别 |
|---|---|
| 脑机接口医疗器械须同时具备四项核心技术特征; 单向采集或单向刺激不属于该类产品 (2026 年第 24 号通告) | 一级 · 国家药监局 |
| 分类编码 12-00 / 09-00 / 19-00 与二类康复的 AI 边界 | 一级 · 国家药监局 |
| YY/T 2029—2026 人工智能脑电数据集质量要求 (2027-09-01 实施) | 一级 · 标准平台 |
| 科创板第五套标准: 预计市值 ≥ 40 亿元, 医药企业需一项核心产品获准开展二期临床 | 一级 · 上交所规则 |
| 港交所 18A: 上市市值 ≥ 15 亿港元, 核心产品通过概念阶段等 | 一级 · 港交所规则 |

## 边界与免责

- 本框架输出的是**尽调流程指标与偏离提示**, 不构成估值结论、不构成投资建议, 亦不构成法律、监管或会计意见。
- 权重、阈值、倍数区间是方法学参数, 使用前须按自身基金口径校准; 里程碑耗时是行业经验区间, 不是对具体标的的工期承诺。
- 控制权推演为按稀释比例线性折算的近似, 不替代律师的章程逐条核对。
- 涉及监管要求时, 一律以现行有效的法规、指导原则与审评要求原文为准。
- 示例数据全部虚构, 不得作为可比交易或估值参照。
- **本项目未授权任何第三方作为官方发行方。** MIT 许可允许任何人复制、修改与再分发本仓库(含商业转售), 这是许可本身的含义, 无法也不会被收回; 但第三方发行不构成作者背书, 修改版也不代表本框架的方法学。如需确认来源, 请比对 `CHANGELOG.md` 与提交历史, 或运行脚本后核对 banner 中的版本号。
